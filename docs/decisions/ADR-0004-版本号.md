# ADR-0004：版本号策略（锁定 0.83.4 + `-dy` 后缀）

- 状态：已接受（2026-08）
- 决策者：多部门头脑风暴 + maintainer

## 背景

上游引擎版本 `0.83.4-r0918ad8-dac2bf5b2` 散落在 `index.html`、`ra2web-sw.js`、引擎内硬编码绝对路径、`assets/releases/` 与 `runtime/releases/` 目录名等多处；上游会持续发布新版本。

## 决策

1. **锁定上游版本 `0.83.4`**，不主动追新；上游仅作参考源。
2. 本项目自有版本号 = `0.83.4-dy.N`（N 为发布序号），git tag `v0.83.4-dy.N`。
3. **版本/路径单点化**：`build-config.json` 是唯一入口（`engine.engineDir` / `engine.runtimeDir` / `engine.upstreamVersion`）。`scripts/build.js` 生成 `__RA2WEB_CONFIG__` 注入，适配层经 `adapter/config.js` 读取。
4. 升级上游 = 改 `build-config.json` + 替换版本目录 + 按 `docs/release-versioning.md` 跑回归（冒烟 + audit + 真机子集）。

## 理由

- 版本号散落是升级漏改的最大隐患（架构团队扫描确认 4 处以上散落点）。
- `-dy` 后缀让"移植层版本"与"上游版本"可追溯、不与上游发布混淆。

## 后果

- 升级上游引擎有一次性适配成本（`scripts/audit-api.js` 上线后自动提示需补齐的 API 面）。
- 上架版本号由 maintainer 唯一管理。

## 复议条件

需要多线上架（体验版/正式版并存）或上游 API 面大幅变化。
