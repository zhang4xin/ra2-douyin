# ADR-0001：单机化范围（配置屏蔽 vs 源码级剔除）

- 状态：已接受（2026-08）
- 决策者：多部门头脑风暴 + maintainer

## 背景

上游引擎 `werhd.min.js` 是压缩产物，内含 WOL/WebSocket 联机逻辑。是否要在源码级删除联机代码以缩小体积并彻底断网？

## 决策

本阶段采用**配置层屏蔽**（`servers.ini` 全部 `available=no` + 遥测禁用），**不**在源码级修改压缩产物。
`build-config.json` 的 `mode.disableMultiplayer` 作为开关；若后续需要彻底剔除联机以省体积，在**打包链**（scripts/build.js，esbuild 打包时 tree-shake / 排除）中处理，而非手改 `werhd.min.js`。

## 理由

- `werhd.min.js` 是上游产物，手改破坏可升级性、且引入不可审计的差异。
- 压缩产物单行 3.4MB，diff/评审不可行。
- 配置屏蔽已能阻断"单机版出现联机入口"这一体验目标。

## 后果

- 引擎内残留的 WOL 代码仍占体积（M3 包体优化时再评估 tree-shake）。
- 需在真机验证"启动/对局全程零外连"（见 docs/security.md 检查清单）。

## 复议条件

包体逼近主包 4MB 上限，且 esbuild 打包链（Phase 1）就绪后。
