# ADR-0002：资源交付方式（git 内 / CDN 远程 / 分包）

- 状态：已接受（2026-08）
- 决策者：多部门头脑风暴 + maintainer

## 背景

全仓 635MB（assets 372MB + runtime 257MB，各含 92 个历史版本目录）。抖音小游戏主包 ≤4MB、总包 ≤24MB。上游资源来自 `stdres.wangerhuoda.cn`、`gmap.wangerhuoda.cn`、`mod.btfs.cn` 等第三方 CDN。

## 决策

1. **仓库瘦身**：仅保留 `0.83.4` 一套版本目录（按 `build-config.json` 的 engine 目录裁剪），历史版本移出 git（大文件不进版本库）。
2. **运行期策略**（M1/M3 逐步落地）：
   - 主包：`game.js` + `adapter/` + 打包后的 `bundle.lib.js` + `bundle.engine.js`（目标 <4MB）。
   - 游戏资源：当前发布版所需资源 hash 固化后进**分包**；仍走 CDN 的资源用 `tt.downloadFile` 落本地文件系统并按 manifest hash 校验。
   - **不引入 Git LFS**：GitHub 免费配额 1GB 远小于存量，且全员装 LFS 摩擦大；资源通过构建脚本从上游拉取固定版本，避免二进制入库。
3. `build-config.json` 的 `whitelistDomains` 是域名白名单单一来源，构建/发布流程据此生成清单。

## 理由

- 二进制入 git 造成 clone 慢、diff 无意义、合并地狱（多部门一致指出的首要协作风险）。
- 分包 + 远程加载是平台硬约束下的唯一可行路线。
- 第三方 CDN 是供应链风险（劫持/下架=游戏不可玩），故必须 hash 校验 + 关键资源离线固化（见 docs/security.md）。

## 后果

- 首次克隆体积大幅下降；构建需要网络拉取上游资源（构建机配置固定版本缓存）。
- 需要资源 manifest 校验机制（M3）。

## 复议条件

自持 CDN/OSS 就绪，或抖音平台包体限制变化。
